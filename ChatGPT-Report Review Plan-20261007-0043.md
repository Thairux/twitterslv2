## 4. SQM Loop 1 - Architecture / Quality Critique

### Strengths

### Remaining concerns

#### Q1 - Ambient inference has an overly aggressive fallback boundary

The application treats practically every inference failure as a reason to generate canned text.

This protects uptime but damages the central product illusion.

For a product whose defining feature is "living AI personas", this should be treated as a major product-quality issue.

Desired behavior:

`LIVE MODEL → LOCAL MODEL → explicit degraded state`

rather than:

`LIVE MODEL → canned sentence`

unless the user has explicitly chosen offline simulation.

#### Q2 - Endpoint health is weaker than inference health

The endpoint probe can succeed through:

- `/v1/models`
- `/models`
- `/health`
- base URL

But actual generation requires:

`POST /v1/chat/completions`

Therefore:

> Endpoint reachable ≠ model inference operational.

The Settings diagnostic should distinguish:

- endpoint reachable
- authentication valid
- model discovered
- selected model valid
- chat completion successful
- inference latency
- fallback reason

#### Q3 - Model ID is critical but insufficiently enforced

The application allows a configured endpoint without necessarily guaranteeing that a valid model is selected.

For gateways that require an explicit model, this can turn a healthy endpoint into repeated 400/404/422 responses followed by canned output.

The application should fail loudly during configuration validation rather than silently discovering the failure during ambient simulation.

#### Q4 - Local inference exists but is not the main ambient fallback

`src/native/inference.ts` provides actual llama.cpp native inference.

However, the ambient social engine primarily routes through `ModelClient`.

Therefore the architecture currently has:

`Cloud endpoint`
→ fallback
→ offline phrase pool

when it could become:

`Cloud endpoint`
→ native/local GGUF
→ offline simulation only if explicitly allowed

That would make the offline-first claim much stronger.

## 5. SQM Loop 2 - Bug Discovery

### BUG-SQM-001 - Live inference can degrade into canned content

**Severity:** HIGH

**Area:** Ambient AI generation

**Symptom:**

The feed/DM simulation can contain large amounts of generic offline-pool text even when the user believes an AI endpoint is configured.

**Root mechanism:**

`resolveAmbientClient()` can produce a client, but `ModelClient.chat()` throws for authentication, model, endpoint, HTTP, timeout, or response errors.

Callers then immediately select offline pools.

**Impact:**

The central TSL experience becomes visibly artificial.

**Recommended fix:**

Introduce a first-class inference result:

```text
LIVE
LOCAL
OFFLINE
FAILED
```

and require the simulation engine to make an explicit policy decision.

Do not silently treat every provider failure as normal offline content.

---

### BUG-SQM-002 - Health probe can report success while generation is unusable

**Severity:** HIGH

**Area:** Model configuration

The probe accepts multiple endpoint paths while actual chat uses `/v1/chat/completions`.

Add an actual authenticated/model-aware inference validation step.

Example:

```text
Connection
  ↓
Model discovery
  ↓
Selected model validation
  ↓
Minimal completion request
  ↓
READY
```

Only then should the ambient engine consider the provider LIVE.

---

### BUG-SQM-003 - Local inference is disconnected from the primary simulation fallback strategy

**Severity:** HIGH

**Area:** Local AI

A real native llama.cpp inference adapter exists, but the ambient generation path does not appear to use it as the normal fallback after cloud inference fails.

Recommended policy:

```text
Provider selected
        ↓
Cloud inference
        ↓ failure
Local selected GGUF
        ↓ failure
Offline simulation
```

The Settings page should expose this priority explicitly.

---

### BUG-SQM-004 - Offline fallback is too successful

**Severity:** MEDIUM/HIGH product-quality issue

Technically, fallback works.

Product-wise, it hides failures.

The system should preserve the fallback but make it configurable:

- Strict AI mode
- Hybrid mode
- Offline simulation mode

In Strict AI mode, failed inference should produce a visible diagnostic/event rather than silently filling the feed with generic phrases.

---

### BUG-SQM-005 - Generic persona-generation fallback

`persona-generator.ts` can convert any model failure into:

`Anon ### / mysterious / generated offline`

This is safe, but can mask broken provider configuration.

Generation UI should clearly say:

`Generated offline because <reason>`

and provide retry/provider diagnostics.
