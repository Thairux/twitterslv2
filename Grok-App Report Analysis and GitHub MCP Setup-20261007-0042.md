## 3. Critical Bug Diagnosis: Offline Pool Fallback (feed full of nonsense)

### Root Cause
The ambient engine (`activity.ts` → `chatter.ts` / `sim-engine.ts`) **always prefers live inference** via `resolveAmbientClient()` (which correctly re-reads endpoint + key + selected model from storage every beat).

However, **any failure** in `ModelClient.chat()` immediately falls back to the offline pools (`OFFLINE_FRIEND_REPLIES`, `OFFLINE_CROWD_REPLIES`, `OFFLINE_POST_STARTERS`).

Common failure triggers (in priority order):
1. **Rate-limit / free-tier 429** on the endpoint (Kilo etc.) — only one retry is attempted.
2. **Auth failure** (empty/missing/expired key, or key not loaded in background context).
3. **Wrong or unsupported model id** in the selected model.
4. **Endpoint returns non-OpenAI-compatible response** → ParseError.
5. Network blip or timeout on ambient path (30 s timeout).

When this happens repeatedly, the feed fills with the same ~20 island-themed phrases → looks like nonsense / repetitive.

### Evidence in code
- `resolveAmbientClient` deliberately ignores the boot-time client (good).
- Every ambient path (posts, replies, DMs, friend-first) has try/catch → offline pool + `noteAmbientFallback()`.
- Settings already shows the last fallback reason via `getAmbientStatus()` (LIVE vs offline + last error).

### Proposed Fix (high priority)
1. **Make fallback rarer and smarter**
   - Add exponential backoff + longer cooldown when 429 is seen.
   - Cache a “last known good” client for a short window (e.g. 60 s) so ambient doesn’t re-probe every 45 s.
   - Prefer local GGUF (llama-cpp-capacitor) when available and endpoint is failing.
2. **Surface the problem better**
   - Make the ambient-status line more prominent (red banner when offline for >2 beats).
   - Add a one-tap “Force live ambient test” button in Settings that runs a real chat and shows the exact error.
3. **Improve offline quality as safety net**
   - Expand offline pools with more variety + persona-specific templates.
   - Mark offline posts with a subtle visual indicator so users know they’re not live.
4. **Immediate diagnostic step for you**
   - Open Settings → look at Ambient engine status line.
   - Run the “Send test chat” button.
   - If it succeeds but ambient still falls back → key/model is not being picked up in background context (race).
